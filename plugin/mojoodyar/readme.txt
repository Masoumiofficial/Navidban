فرم «خبرم کن» برای محصول و تنوع ناموجود، نمایش خودکار و شورت‌کد، صف ارسال
پس‌زمینه و پیامک ایرانی. تأیید دومرحله‌ای اختیاری است.

== Description ==

موجودیار وقتی کالایی تمام می‌شود، مشتری را از دست نمی‌دهد: مشتری شماره یا
ایمیل می‌گذارد، به‌محض بازگشت موجودی خبر می‌گیرد.

**آنچه این افزونه را متفاوت می‌کند**

* **محل فرم.** نمایش خودکار نزدیک پیام ناموجود؛ شورت‌کد `[mojoodyar_form]`
  در همان محصول یا `[mojoodyar_form product_id="123"]` در صفحهٔ دیگر. برای
  محصول متغیر انتخاب‌گر مستقل تنوع ناموجود فراهم است.
* **بارگذاری شرطی.** استایل و اسکریپت در صفحهٔ محصول واجد شرایط یا صفحه‌ای
  با شورت‌کد واجد شرایط بارگذاری می‌شود. در هارنس، خانه و محصول موجودِ بدون
  شورت‌کد صفر دارایی داشتند؛ شبکه و کوئری نصب واقعی هنوز اندازه‌گیری نشده‌اند:
  `docs/PERFORMANCE.md`.
* **PHP 7.4 تا 8.3.** بدون Composer، بدون npm، بدون build، بدون IonCube،
  بدون کلید لایسنس، بدون تماس با سرور ما.
* **اعلام منصفانه.** با موجودی مدیریت‌شده و این تنظیم روشن، حداکثر به تعداد
  واحد قابل تخصیص از منتظران تأییدشده و قدیمی‌تر در صف اعلان قرار می‌گیرند.
* **تشخیص موجودی دولایه.** هوک‌های ووکامرس و پایش تطبیقی وابسته به اجرای
  WP-Cron برای تغییرهای بیرون از هوک.
* **تأیید دومرحله‌ای اختیاری** پیش‌فرض خاموش است؛ حالت روشن پیش از اعلان
  موجودی به تأیید پیوند نیاز دارد، اما ارسال پیام تأیید هزینه دارد. ایمیل
  اعلان پیوند لغو دارد؛ در پیامک، متن و الگوی انتخابی فروشگاه تعیین‌کننده است.
* **پنل فارسی راست‌چین** با تاریخ شمسی، ارقام فارسی، فیلتر و خروجی CSV.

**کانال‌ها:** ایمیل (wp_mail) · ملی‌پیامک · آی‌پی‌پنل · کاوه‌نگار · درگاه
عمومی REST با محافظت SSRF.

== Installation ==

1. zip را در **افزونه‌ها → افزودن → بارگذاری** نصب و فعال کنید.
2. یک محصول را ناموجود کنید و صفحه‌اش را باز کنید. قالب باید `wp_footer()`
   داشته باشد و جاوااسکریپت فعال باشد؛ اگر قالب جای مناسبی ندارد، شورت‌کد را
   بیرون هر فرم دیگر در محتوای محصول بگذارید.
3. در **موجودیار → ابزارها** یک ایمیل آزمایشی بفرستید و دریافت آن را بررسی کنید.

== Frequently Asked Questions ==

= آیا بدون ووکامرس کار می‌کند؟ =
نه. برای فرم روی صفحهٔ محصول و تشخیص موجودی، ووکامرس لازم است.

= آیا داده‌ای به سرور شما می‌فرستد؟ =
نه. تنها تماس خروجی، به درگاه پیامکی است که خودتان تنظیم می‌کنید.

= با حذف افزونه داده‌ها پاک می‌شوند؟ =
نه، مگر گزینهٔ «حذف داده هنگام حذف افزونه» را روشن کرده باشید.

= می‌توانم فقط پیامک داشته باشم؟ =
بله. تنظیمات → کانال‌ها → پیامک را روشن کنید و حالت انتخاب را روی «پیامک» بگذارید.

= فرم را چطور در جای دلخواه بگذارم؟ =
در محتوای محصول `[mojoodyar_form]` یا در صفحهٔ دیگر
`[mojoodyar_form product_id="123"]` را در بلوک شورت‌کد قرار دهید. محصول باید
ناموجود و قابل نمایش باشد. فرم صریح همان محصول جای فرم خودکار را می‌گیرد.

= روی چه نسخه‌ای تست شده است؟ =
PHP-WASM 7.4.33 و 8.3.36 با هارنس؛ آزمون محدود WordPress 6.4.5 و
WooCommerce 9.0.0 در Playground با SQLite و jsdom. MySQL، تحویل واقعی
پیامک/ایمیل و سازگاری همهٔ قالب‌ها آزموده نشده‌اند؛ `docs/TEST-REPORT.md`.

== Compatibility ==

این جدول عمداً «تست‌شده» و «آزمون‌نشده» را از هم جدا می‌کند. جای تیک سبز،
واقعیت نوشته شده است.

| محیط | وضعیت |
|---|---|
| PHP 7.4.33 و 8.3.36 | PHP-WASM؛ هرکدام ۴۱۱ + ۶۲۵ + ۱۸۰ بررسی با stub، ۰ خطا |
| PHP 8.0 تا 8.2 | همان کد؛ آزمون جداگانه اجرا نشده |
| PHP 8.4 | داده در دسترس نیست |
| وردپرس ۶.۴.۵ و ووکامرس ۹.۰.۰ | آزمون محدود Playground با SQLite و jsdom؛ تحویل واقعی انجام نشده |
| نسخه‌های بالاتر وردپرس/ووکامرس | حداقل اعلام‌شده ۶.۴/۹.۰؛ سایر نسخه‌ها آزموده نشده‌اند |
| HPOS (جدول سفارش‌ها) | سازگاری در کد اعلام شده؛ روی نصب واقعی تست نشده |
| وردپرس چندسایتی | کد به `wp_posts` وابسته نیست؛ تست نشده |
| WPML / چندزبانه | داده در دسترس نیست |
| ترجمهٔ رابط کاربری | رابط کاربری فارسی است و لایهٔ ترجمه ندارد؛ خارج از دامنهٔ این نسخه |

جزئیات آزمون خودکار و محدودیت محیط در `docs/TEST-REPORT.md` است. روی هاست،
قالب و درگاه واقعی فروشگاه خودتان نیز پیش از فروش آزمون کنید.

== Changelog ==

= 1.0.0 =
اولین انتشار عمومی. همهٔ موارد زیر در همین نسخه هست و آزمون‌شده است:

* نمایش خودکار فرم نزدیک وضعیت ناموجود؛ شورت‌کد محصول جاری یا شناسهٔ صریح؛ انتخاب تنوع ناموجود بدون تکرار فرم خودکار.
* دو کانال: پیامک (ملی‌پیامک با الگو/bodyId، کاوه‌نگار، آی‌پی‌پنل، درگاه REST عمومی) و ایمیل با پوستهٔ اختصاصی.
* صف پس‌زمینه با قفل ردیف، بازپس‌گیری ردیف رهاشده، عقب‌نشینی ۱۵ دقیقه/۱ ساعت/۶ ساعت، سقف تلاش قابل تنظیم و نرخ ارسال در دقیقه.
* ارسال منصفانه: برای موجودی مدیریت‌شده، حداکثر به تعداد واحد قابل تخصیص از منتظران تأییدشده؛ قدیمی‌ترین درخواست اول.
* تشخیص موجودی دولایه: قلاب‌های ووکامرس + پایش با فاصلهٔ پیش‌فرض ۱۵ دقیقه، وابسته به WP-Cron (اجرای اول فقط عکس‌برداری می‌کند).
* پنل فارسی راست‌به‌چپ: داشبورد، لیست انتظار، آمار، پیگیری تلفنی مرحله‌ای، تنظیمات، ابزارها، راهنما و گزارش رویدادها با توضیح فارسی و لاگ خام.
* تأیید دو مرحله‌ای اختیاری، خروجی CSV با BOM، تاریخ شمسی، ارقام فارسی.
* بدون Composer، بدون npm، بدون build، بدون IonCube، بدون لایسنس‌سرور و بدون هیچ تماس با سرور سازنده.
