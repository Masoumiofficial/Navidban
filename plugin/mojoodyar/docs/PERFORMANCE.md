## ۲) اندازهٔ فایل‌های فرانت

اندازه‌گیری محلی با `wc -c` و `gzip -9 -n` روی فایل‌های بسته؛
حجم انتقال واقعی به تنظیمات سرور و کش بستگی دارد و اینجا اندازه‌گیری نشده است.

| فایل | خام | gzip |
|---|---|---|
| `assets/css/mojoodyar-front.css` | 5,983 B | 2,021 B |
| `assets/js/mojoodyar-front.js` | 12,901 B | 4,108 B |
| **جمع** | **18,884 B** | **6,129 B** |

نتیجه: 6,129 بایت فشرده در برابر بودجهٔ 12,288 بایت — در محدوده.

این عدد شبیه‌سازی gzip است، نه اندازهٔ HAR و نه ادعایی دربارهٔ همهٔ سرورها.

## ۳) بارگذاری به تفکیک نوع صفحه

`tests/queries.php` از stub وردپرس/ووکامرس و SQLite استفاده می‌کند؛
این اعداد برای همان سناریوها هستند، نه ضبط شبکه یا شمارش کویری نصب واقعی.
یک شورت‌کد واجد شرایط در هر صفحه نیز دارایی فرم را بارگذاری می‌کند.

| صفحه | دارایی صف‌شده | style | script | SQL مستقیم در stub | بایت HTML فرم |
|---|---|---|---|---|---|
| صفحهٔ خانه (غیرمحصول) | 0 | 0 | 0 | 0 | 0 |
| صفحهٔ محصول موجود | 0 | 0 | 0 | 0 | 0 |
| صفحهٔ محصول ناموجود | 2 | 1 | 1 | 0 | 2,105 |
| صفحهٔ محصول متغیر با یک تنوع ناموجود | 2 | 1 | 1 | 0 | 2,405 |

SQL مستقیم در سناریوهای stub از این بودجه عبور نکرد؛ نتیجه برای دیتابیس واقعی نامعلوم است.

### محدودیت این اندازه‌گیری (مهم)

هارنس `get_option()` و `wc_get_product()` را از حافظه می‌خواند؛
کویری‌های هسته و ووکامرس، بارگذاری متادیتا و فرزندان محصول متغیر،
و تآثیر کش پایگاه داده در این جدول دیده نمی‌شوند. شمار واقعی پرس‌وجوی
اضافه، مخصوصاً برای محصولی با تنوع‌های زیاد، **اندازه‌گیری نشده است**.
با Query Monitor روی نصب آزمایشی، همان URL را با افزونه فعال و غیرفعال،
در شرایط کش یکسان مقایسه کنید؛ روش در `docs/QA-CHECKLIST.md` ثبت است.

## ۴) TTFB — اندازه‌گیری نشد

TTFB به میزبان، نسخهٔ PHP، OPcache، کش صفحه، افزونه‌های دیگر و پیکربندی
MySQL بستگی دارد. ادعای عددی برای آن بدون اندازه‌گیری روی سایت واقعی،
ساختگی است؛ بنابراین این پرونده عددی اعلام نمی‌کند.

روش بازتولید روی کپی آزمایشی فروشگاه: یک URL ثابت محصول ناموجود را انتخاب
کنید، با کش و بار سرور مشابه چند بار با افزونه غیرفعال و چند بار با افزونه
فعال اندازه بگیرید؛ تکرارها و شرایط را ثبت و میانه‌ها را مقایسه کنید. مقایسهٔ
دو محصول متفاوت اثر افزونه را جدا نمی‌کند. نمونهٔ یک دسته:

```bash
for i in 1 2 3 4 5; do
  curl -s -o /dev/null -w '%{time_starttransfer}\n' https://shop.example/product/out-of-stock/
done
```

این دستور را جداگانه در هر دو وضعیت تکرار کنید؛ نتیجه برای هر هاست متفاوت است.

## ۵) ثبت شبکهٔ واقعی

**اندازه‌گیری نشد.** هیچ HARای ارایه نشده است.

روش: در Chrome → DevTools → Network، گزینهٔ «Disable cache» را بزنید،
صفحهٔ خانه، یک محصول موجود و یک محصول ناموجود را باز کنید، سپس
«Save all as HAR» و:

```bash
tools/har-audit.sh --har ~/mojoodyar.har
```

در آن حالت، بایت‌ها و درخواست‌ها از خودِ ضبط شبکه استخراج می‌شوند، نه از حدس.

- هیچ عددی از «تعداد بازدید» یا «نرخ تبدیل».
