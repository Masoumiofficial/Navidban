# مشخصات موجودیار ۱.۰.۰

**نام:** موجودیار (Mojoodyar)
**نامک/اسلاگ:** `mojoodyar`
**نسخه:** ۱.۰.۳ — ۱۴۰۵/۰۸/۰۴ (۲۰۲۶-۱۰-۲۶)
**پروانه:** GPLv2 یا بالاتر
**حداقل‌ها:** WordPress 6.4 · WooCommerce 9.0 · PHP 7.4 (سازگار تا 8.3؛ grammer 8.4 تست نشده)

---

## ۱) مسئله

فروشگاه ایرانی مواجه است با: کالایی که تمام شده، مشتری‌ای که رفته و برنمی‌گردد
چون کسی به او خبر نمی‌دهد. راه‌حل رایج در بازار، افزونه‌هایی هستند که:

- در **همهٔ** صفحات سایت CSS/JS بار می‌کنند (شکایت مستند کاربران افزونهٔ
  پیشرو، پاسخ پشتیبانی: «در آپدیت بعدی» که هرگز نیامد)؛
- برای هر بازدید یک یا چند کوئری اضافه می‌زنند؛
- روی PHP 8.4 به‌روز شده‌اند اما PHP 7.4 را رها کرده‌اند — در حالی که بخش بزرگی
  از هاست‌های اشتراکی ایران روی 7.4 مانده‌اند؛
- به سرور سازنده وابسته‌اند (لایسنس/IonCube).

## ۲) وعدهٔ موجودیار

1. **صفر بایت** در همهٔ صفحاتی که صفحهٔ محصولِ ناموجود نیستند.
2. **بدون Composer، بدون npm، بدون build، بدون IonCube، بدون لایسنس.**
3. **PHP 7.4 تا 8.3** با یک codebase؛ بدون syntax جدیدتر از 7.4.
4. همهٔ جدول‌ها **InnoDB**؛ همهٔ کوئری‌ها با `$wpdb->prepare()`.
5. صف ارسال پس‌زمینه با محدودیت نرخ، بازهٔ مجاز ارسال و backoff نمایی.
6. **اعلام به تعداد موجودی**: ۵ واحد برگشته = ۵ اعلان، نه ۵۰۰۰.

## ۳) دامنهٔ نسخهٔ ۱.۰.۰ (آنچه هست)

| قابلیت | وضعیت |
|---|---|
| فرم «خبرم کن» روی محصول/تنوع ناموجود | پیاده‌سازی شد |
| ایمیل + سه درگاه پیامک ایرانی + یک درگاه عمومی REST | پیاده‌سازی شد |
| ارسال پیامک با «الگو» (bodyId) و مقدارهای `{0}`…`{3}` به ترتیب شماره | پیاده‌سازی شد؛ بررسی متن با قواعد تأیید درگاه پیش از ارسال |
| تأیید دومرحله‌ای (double opt-in) با انقضای ۴۸ ساعته | پیاده‌سازی شد؛ **پیش‌فرض از ۱.۰.۴ خاموش است** |
| انتخاب کانال فرم: پیامک اول / ایمیل اول / هر دو | پیاده‌سازی شد؛ پیش‌فرض `sms_first` |
| گرفتن نام و نام خانوادگی و استفادهٔ آن در پیام و پیگیری تماس | پیاده‌سازی شد؛ نام در پیامک (`{0}`) و ایمیل (`{customer_name}`) |
| تیک «تماس گرفته شد» با تاریخ و کاربر، فیلتر و خروجی CSV | پیاده‌سازی شد؛ فقط یادداشت دستی، بدون یکپارچه‌سازی تلفنی |
| روشن/خاموش کردن فیلد ایمیل و موبایل در فرم | پیاده‌سازی شد؛ فیلد بدون درگاهِ آماده نمایش داده نمی‌شود |
| قالب ایمیل HTML شیشه‌ای با نسخهٔ متنی جایگزین | پیاده‌سازی شد؛ آمار تحویل اندازه‌گیری نشد |
| لغو اشتراک یک‌کلیکی از داخل هر پیام | پیاده‌سازی شد |
| تشخیص موجودی دولایه (هوک‌های ووکامرس + پایش تطبیقی) | پیاده‌سازی شد |
| صف ارسال با rate limit، بازهٔ زمانی، backoff، قفل | پیاده‌سازی شد |
| پنل مدیریت راست‌چین فارسی با تاریخ شمسی و ارقام فارسی | پیاده‌سازی شد |
| خروجی CSV با BOM و مقاوم‌سازی فرمول | پیاده‌سازی شد |
| حذف داده هنگام حذف افزونه (پیش‌فرض خاموش) | پیاده‌سازی شد |

## ۴) دامنهٔ منفی — آنچه عمداً ساخته نشد

این فهرست بخشی از قرارداد است، نه فراموشی:

- اعلان تغییر وضعیت سفارش (این کار افزونهٔ سفارش است، نه لیست انتظار).
- واتس‌اپ/تلگرام (نیاز به سرور بیرونی و توکن متغیر).
- لیست انتظار «نوبت/وقت» (صف نوبت‌دهی) — نامزد نسخهٔ ۱.۱.
- باشگاه مشتریان، امتیاز، کش‌بک.
- بیش از سه درگاه پیامک اختصاصی + یک درگاه عمومی REST.
- چندزبانه بودن رابط افزونه.
- فرم در سبد خرید / تسویه حساب.
- اپ موبایل یا دسکتاپ.
- صفحه‌ساز کشیدن‌ورهاکردن.

## ۶) تعریف شکست

نسخهٔ ۱.۰.۰ شکست‌خورده تلقی می‌شود اگر:

- روی PHP 7.4 خطای parse بدهد؛
- در صفحهٔ خانه یک درخواست شبکهٔ اضافه تولید کند؛
- جدولی با موتور MyISAM بسازد؛
- پیام بدون پیوند لغو بفرستد؛
- در حالت «موجودی ۵» بیش از ۵ اعلان بفرستد.

## ۷) آنچه اندازه‌گیری نشد

- عملکرد روی MySQL واقعی با ۱۰۰٬۰۰۰ ردیف (هارنس SQLite است؛
  `tests/load.php` می‌گوید صریحاً «بنچمارک MySQL نیست»).
- سازگاری با WordPress 7.0/7.1 و WooCommerce 11 (نسخه‌هایی که در زمان
  نوشتن این سند هنوز منتشر نشده یا در دسترس نبوده‌اند).
- شبکهٔ چندسایتی (network-activate) روی نصب واقعی.
- HPOS روشن/خاموش روی نصب واقعی (کد از API رسمی استفاده می‌کند و به جدول
  `posts` وابسته نیست، اما این ادعا با اجرای واقعی تأیید نشده است).

فهرست کامل و به‌روز: `docs/QA-CHECKLIST.md`.
