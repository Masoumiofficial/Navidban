### محدودیت این اندازه‌گیری (مهم)

هارنس، `get_option()` را از حافظه می‌خواند و بنابراین کوئری خواندن آپشن
را در شمارش نمی‌بیند. در وردپرس واقعی `navidban_settings` با
`autoload = false` ذخیره می‌شود (عمدی: تا در هیچ صفحه‌ای بارگذاری نشود)،
پس نخستین خواندن آن در صفحهٔ محصول ناموجود **۱ کوئری** است.

| صفحه | کوئری اندازه‌گیری‌شده در هارنس | تخمین وردپرس واقعی |
|---|---|---|
| صفحات غیرهدف | ۰ | ۰ (تنظیمات خوانده نمی‌شود) |
| محصول ناموجود | ۰ | ۱ (خواندن آپشن؛ در بودجهٔ ≤۳ جا می‌شود) |

تخمین ستون آخر **اندازه‌گیری نشده** است؛ روی نصب واقعی با
Query Monitor قابل تأیید است و در `docs/QA-CHECKLIST.md` ثبت شده.

## ۴) TTFB — اندازه‌گیری نشد

TTFB به میزبان، نسخهٔ PHP، OPcache، کش صفحه، افزونه‌های دیگر و پیکربندی
MySQL بستگی دارد. ادعای عددی برای آن بدون اندازه‌گیری روی سایت واقعی،
ساختگی است؛ بنابراین این پرونده عددی اعلام نمی‌کند.

روش بازتولید (روی سایت واقعی، با داده‌های واقعی):

```bash
# ۳ بار اندازه‌گیری صفحهٔ محصول موجود (پایه)
for i in 1 2 3; do
  curl -s -o /dev/null -w '%{time_starttransfer}\n' https://shop.example/product/in-stock/
done
# ۳ بار اندازه‌گیری صفحهٔ محصول ناموجود (هدف)
for i in 1 2 3; do
  curl -s -o /dev/null -w '%{time_starttransfer}\n' https://shop.example/product/out-of-stock/
done
```

سپس میانهٔ دو مجموعه را کم کنید. اگر اختلاف از ۵ میلی‌ثانیه بیشتر بود، پیش از
انتشار گزارش دهید — بودجه نقض شده است.

## ۵) ثبت شبکهٔ واقعی

**اندازه‌گیری نشد.** هیچ HARای ارائه نشده است.

روش: در Chrome → DevTools → Network، گزینهٔ «Disable cache» را بزنید،
صفحهٔ خانه، یک محصول موجود و یک محصول ناموجود را باز کنید، سپس
«Save all as HAR» و:

```bash
tools/har-audit.sh --har ~/navidban.har
```

در آن حالت، بایت‌ها و درخواست‌ها از خودِ ضبط شبکه استخراج می‌شوند، نه از حدس.
