# امنیت نویدبان

## گزارش آسیب‌پذیری

- مسیر: issue خصوصی در مخزن پروژه، یا ایمیل نگه‌دارندهٔ افزونه.
- **تعهد زمانی:** پاسخ اولیه حداکثر **۲۴ ساعت کاری** (هدف: **۴ ساعت**).
- پاسخ همیشه شامل **تحلیل واقعی** است: چه کدی، چه پیش‌شرطی، چه اثری، و اگر
  گزارش نادرست بود، دلیل فنی نادرست بودن. پاسخ «مشکلی نیست» یا «خیالتان
  راحت» داده نمی‌شود.
- اگر گزارش درست باشد: وصله، ورودی CHANGELOG با **سطح خطر صریح**
  (بحرانی/بالا/متوسط/پایین) و اعتبار برای گزارش‌دهنده (در صورت تمایل).

نسخه‌های پشتیبانی‌شده: آخرین نسخهٔ minor.

## ماتریس S1–S15

| # | کنترل | وضعیت | شاهد در کد |
|---|---|---|---|
| S1 | CSRF | پاس | REST: `X-WP-Nonce` با `wp_verify_nonce(..., 'wp_rest')` در `Rest::can_subscribe()`؛ AJAX: nonce اختصاصی `navidban_subscribe`؛ همهٔ فرم‌های ادمین `wp_nonce_field` + `check_admin_referer` |
| S2 | مجوز | پاس | `Capabilities::MANAGE = navidban_manage` در همهٔ عملیات ادمین/ابزار/خروجی؛ `navidban_view_reports` برای گزارش‌ها |
| S3 | اعتبارسنجی ورودی | پاس | `Support\Validator`: موبایل با `^09\d{9}$` (پس از نرمال‌سازی ارقام فارسی/عربی و `+98`)، ایمیل با `is_email()`/فیلتر PHP؛ `sanitize_text_field` روی همهٔ ورودی‌های عمومی |
| S4 | خروجی | پاس | `esc_html`/`esc_attr`/`esc_url`/`esc_textarea` در همهٔ viewها؛ هیچ `echo $var` خام (بازبینی دستی + `tools/check-methods.js`) |
| S5 | تزریق SQL | پاس | همهٔ مقادیر از `$wpdb->prepare()`؛ تنها رشتهٔ تزریق‌شده، نام جدول از ثابت‌های داخلی است. `tools/verify-release.py` الگوی «`$wpdb` بدون prepare» را می‌گیرد |
| S6 | Rate limit | پاس | `Subscribe::RATE_LIMIT = 5` در ۶۰ دقیقه بر پایهٔ `ip_hash` در جدول `nvb_logs`؛ nonce یک‌بارمصرف REST/AJAX |
| S7 | SSRF | پاس | `Logic\HttpGuard::check()`: فقط `https`؛ رد credential در URL؛ کاراکتر کنترلی/فاصله ممنوع؛ IP literal فقط اگر عمومی باشد (`FILTER_FLAG_NO_PRIV_RANGE | NO_RES_RANGE`)؛ نام‌های `localhost`, `*.internal`, `*.local`, `metadata.google.internal` مسدود. مقصد فقط از تنظیمات **مدیر** خوانده می‌شود، هرگز از ورودی کاربر |
| S8 | Path traversal | پاس | هیچ مسیری از ورودی ساخته نمی‌شود؛ viewها با `NAVIDBAN_DIR` ثابت include می‌شوند |
| S9 | XSS ذخیره‌شده | پاس | ایمیل/موبایل نرمال‌شده و محدودشده پیش از ذخیره؛ در نمایش هم escape می‌شوند |
| S10 | افشای مسیر | پاس | پوشهٔ `src/` وجود ندارد؛ دارایی‌ها در `assets/` با نام عمومی |
| S11 | حداقل‌سازی داده | پاس | IP خام ذخیره نمی‌شود؛ فقط `sha256(salt . ip)` در `ip_hash`؛ توکن‌ها تصادفی و یکتا؛ uninstall کامل (پیش‌فرض خاموش) |
| S12 | Double opt-in | پاس | `Consent::generate_token()` ۶۴ کاراکتر، انقضای پیش‌فرض ۴۸ ساعت، `confirm_expires_at` در دیتابیس؛ تا تأیید نشدن هیچ اعلانی ارسال نمی‌شود |
| S13 | لغو اشتراک | پاس | `Consent::unsubscribe_url()` در **هر** پیام (ایمیل و پیامک، هر چهار درگاه)؛ بدون ورود |
| S14 | لاگ امنیتی | پاس | `Logger::log('warning','subscribe_rate_limited',...)` برای تلاش‌های غیرعادی؛ لاگ بدون دادهٔ شخصی |
| S15 | وابستگی‌ها | پاس | صفر کتابخانهٔ bundled؛ `tools/` و `tests/` از بسته حذف می‌شوند؛ `composer.json` و `package.json` وجود ندارد |

## نمک هش IP

`ip_hash = sha256( wp_salt('auth') . $ip )`. نمک از `wp_salt()` می‌آید؛ بنابراین
هش برای هر نصب یکتاست و با جابه‌جایی دیتابیس بی‌معنی می‌شود.

محدودیت مستند: هش IP، IP را غیرقابل‌بازگشت نمی‌کند (فضای IPv4 کوچک است و
حملهٔ دیکشنری ممکن است). هدف هش، جلوگیری از خواندن IP خام توسط کسی است که
دیتابیس را می‌بیند، نه ناشناس‌سازی مطلق.

## داده‌های شخصی

| داده | محل | نگهداشت |
|---|---|---|
| ایمیل | `nvb_waitlists.email` | تا `retention_days` (۱۸۰) پس از اعلان، سپس حذف |
| موبایل | `nvb_waitlists.phone` | همان |
| هش IP | `nvb_waitlists.ip_hash`, `nvb_logs.ip_hash` | لاگ‌ها ۳۰ روز |
| توکن | `nvb_waitlists.token` | با حذف ردیف |

گزینهٔ «حذف داده هنگام حذف افزونه» **پیش‌فرض خاموش** است تا حذف ناخواستهٔ
افزونه، لیست مشتریان فروشگاه را نابود نکند.

## آنچه ادعا نمی‌شود

- تست نفوذ مستقل انجام نشده است.
- سازگاری با WAF/مودسکیوریتی خاصی تست نشده است.
- محافظت در برابر حملهٔ DDoS لایهٔ شبکه وظیفهٔ افزونه نیست.
- ناشناس‌سازی کامل IP (ادعای «کاملاً ناشناس») داده نشده است؛ توضیح بالا.
- **DNS rebinding:** گارد، رشتهٔ URL را بررسی می‌کند، نه IP نهایی که
  `wp_remote_*` حل می‌کند. اگر مدیر خودش یک دامنهٔ عمومی ثبت کند که به
  `169.254.169.254` اشاره می‌کند، گارد آن را نمی‌گیرد. علت پذیرش این ریسک:
  ورودی این فیلد فقط از مدیر سایت می‌آید و به اندازهٔ دسترسی خودِ مدیر
  خطرناک است؛ بستن آن نیازمند pin کردن DNS در لایهٔ HTTP است که در
  WordPress بدون جایگزینی کامل `WP_Http` ممکن نیست.
